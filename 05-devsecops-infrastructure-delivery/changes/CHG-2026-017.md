# CHG-2026-017 · Protect demo asset storage

**Synthetic change-review exercise.** Requester role: application owner. Risk: public exposure of an asset bucket. No real change approval or deployment occurred.

## Request and decision

The scenario requests public object storage for demo assets. The proposed alternative keeps the bucket private and uses an approved application/CDN delivery path. That application/CDN is a design choice, not a resource implemented by this foundation.

## Executed local evidence

The normalized policy gate blocks a public-storage fixture and passes the committed safe fixture. See Python CLI tests and the offline suite. Terraform formatting/static scans are separate from provider validation, which is marked environment-blocked in the packaged evidence.

## Acceptance before a real change

Validate content-delivery behavior, effective anonymous denial, authorized consumer access, cost and rollback. Record the accountable approver and actual target only in a real change system.

## Rollback

Stop release on failed acceptance. Inspect the plan for a code revert or corrective change; do not assume a Git revert restores data or safely reverses infrastructure. Preserve audit storage and keys.
