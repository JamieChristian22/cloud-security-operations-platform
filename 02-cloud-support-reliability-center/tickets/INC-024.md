# INC-024 — Teams user cannot schedule meeting

**Priority:** P3  
**Category:** M365  
**Status:** Resolved  
**Resolution time:** 1.6 hours  

## User / Service Impact
A limited user/service workflow was affected with no broad outage. Scope was confirmed before any configuration change.

## Initial Hypotheses
1. Authentication/identity or authorization mismatch.
2. Network, DNS, platform, or dependency failure.
3. Application/configuration regression introduced by a recent change.

## Evidence Collected
- **Primary evidence:** Account licensed, but Teams service plan was disabled.
- **Commands / consoles used:** `license assignment review; service health`
- Checked recent changes and compared expected state to actual state before remediation.

## Investigation
The incident was reproduced or validated from the affected path. The investigation moved layer-by-layer from identity to network/platform to application behavior, avoiding broad changes. Evidence was compared against a known-good or expected configuration. The failing control was isolated before remediation.

## Root Cause
**License service plan disabled.**

## Resolution
Enabled approved service plan and verified propagation. The original user/service path was retested after the change and the failure condition no longer reproduced.

## Validation
- Confirmed the affected identity/service could complete the expected operation.
- Rechecked logs/health state for new errors.
- Confirmed the fix did not require broader privilege or public exposure than necessary.

## Prevention / Follow-up
Converted the RCA into one or more preventive controls: automated validation, alert tuning, runbook improvement, stronger role/group mapping, required tagging, secret scanning, or change-review criteria.

## Customer Communication
Shared impact, restoration status, and any required user action in plain language. Sensitive internal security details and credentials were not included.
